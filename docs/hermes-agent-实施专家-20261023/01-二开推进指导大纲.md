# 二开推进指导大纲（开源可变更项与安全规范）

## 一、适用范围与总原则

**适用**：hermes-agent `0.21.3` 及后续版本，纯本地、个人自用场景。

**总原则**：

| 原则 | 含义 | 判定标准 |
| --- | --- | --- |
| 边缘优先 | 能力长在插件 / 技能 / MCP，不长在核心 | 变更不触碰 `run_agent.py`、`cli.py`、`gateway/run.py`、`hermes_cli/main.py` |
| 最小改动 | 能用配置解决就不写代码，能写技能就不写插件 | 变更层级尽可能低 |
| 可回滚 | 每一层都能单独撤销 | 有明确回滚路径与备份点 |
| 可验证 | 变更前有基线，变更后可复查 | 有对照测试或可复现命令 |
| 数据主权 | 个人数据默认不出本机 | 出网组件需逐项确认并记录 |

## 二、变更分级与审批矩阵

风险等级定义：**绿** = 无核心影响；**黄** = 影响个人运行，可快速回滚；**红** = 触及核心不变量，需完整验证；**黑** = 禁止。

| 编号 | 层级 | 可变更对象 | 典型改法 | 风险 | 审批要求 |
| --- | --- | --- | --- | --- | --- |
| C0 | 配置层 | `~/.hermes/config.yaml`、`hermes tools`、`hermes setup` | 选模型、开关工具集、cron、皮肤、辅助模型路由 | 绿 | 无 |
| C1 | 技能层 | `~/.hermes/skills/<name>/SKILL.md` | 固化个人流程、领域知识、固定话术 | 绿 | 涉及执行命令时做安全评审 |
| C2 | 插件层 | `~/.hermes/plugins/<name>/` | 私有工具、钩子、CLI 子命令、平台接入 | 黄 | 安全评审（权限 / 网络 / 凭证） |
| C3 | MCP 层 | 外部 MCP Server | 接数据库、内部 API、私有 SaaS | 黄 | 数据流向评审 |
| C4 | Provider 层 | model / memory / context-engine / platform provider | 本地模型、本地记忆、渠道适配 | 黄至红 | 架构评审 + E2E |
| C5 | 工具层 | 仓内 `tools/`、`toolsets.py` | 新增或调整工具与工具集 | 红 | 架构评审 + 测试 |
| C6 | 核心层 | `run_agent.py`、`cli.py`、`gateway/run.py`、`hermes_cli/main.py` | 单点补丁 | 黑（插件禁止）/ 红（个人 fork） | 双重评审 + 不变量测试 |

## 三、可变更项细目

### 3.1 C0 配置层

允许变更：

- 模型与供应商：`hermes model`，或 `config.yaml` 中的 provider / model / fallback。
- 工具集：`hermes tools`，按平台启用或禁用；核心列表见 [toolsets.py](../../toolsets.py)。
- 辅助模型：`auxiliary:` 下的 curator / vision / embedding / title / session_search / compression，可分别指向本地模型。
- 自动化：cron 任务、投递渠道、失败告警。
- 记忆后端：`memory.provider`。
- 显示与皮肤：`hermes config set`、skin。

约束：

- **非密钥配置不得写入 `.env`**；`.env` 只放凭证。
- 修改前备份 `~/.hermes/config.yaml`。
- 配置变更后必须重启常驻进程才生效。

### 3.2 C1 技能层

目录形态（个人技能建议放 `~/.hermes/skills/`，不污染仓库）：

```text
~/.hermes/skills/my-daily-brief/
└── SKILL.md
```

前置元数据参考仓内样例 [SKILL.md](../../skills/apple/apple-reminders/SKILL.md)：

```markdown
---
name: my-daily-brief
description: "每日简报：汇总日程、未读邮件、待办与昨日会话要点"
version: 1.0.0
author: local
license: MIT
platforms: [macos]
metadata:
  hermes:
    tags: [personal, briefing, cron]
prerequisites:
  commands: []
---
```

允许变更：`name`、`description`、`version`、`platforms`、`metadata.hermes.tags`、`prerequisites`、正文步骤。

约束：

- `platforms` 写错会导致技能在目标渠道不可见。
- 技能正文是给模型读的指令，不是代码；避免写入密钥、内网地址、个人隐私。
- 技能内调用的命令必须是本机已安装且可幂等执行的。

### 3.3 C2 插件层

目录形态：

```text
~/.hermes/plugins/my-ops/
├── plugin.yaml
├── __init__.py
└── my_ops.py
```

`register(ctx)` 可用的注册面（已核实于 [plugins.py](../../hermes_cli/plugins.py)）：

| 方法 | 用途 |
| --- | --- |
| `register_tool` | 注册模型可调用的工具 |
| `register_hook` | 注册生命周期钩子 |
| `register_cli_command` | 注册 `hermes` 子命令 |
| `register_platform` | 注册消息平台适配器 |
| `register_skill` | 随插件分发技能 |
| `register_auxiliary_task` | 注册辅助模型任务 |
| `register_memory_provider` | 注册记忆后端 |
| `register_context_engine` | 注册上下文引擎 |
| `register_middleware` | 注册中间件 |
| `register_system_prompt_section` | 注入系统提示片段（需谨慎） |
| `register_redaction_patterns` | 注册日志脱敏规则 |

可用钩子：`pre_tool_call`、`post_tool_call`、`pre_llm_call`、`post_llm_call`、`on_session_start`、`on_session_end`。

最小骨架：

```python
# ~/.hermes/plugins/my-ops/__init__.py
def register(ctx):
    ctx.register_tool(
        name="ops_query_ledger",
        description="查询本地运维台账（只读）",
        parameters={"type": "object", "properties": {"limit": {"type": "integer"}}},
        handler=query_ledger,
    )
    ctx.register_hook("pre_tool_call", audit_write_ops)
    ctx.register_cli_command("ops", build_parser)
```

约束：

- **插件禁止修改核心文件**，只能在 ABC / 钩子 / `ctx` 面内工作。
- 插件不得读取 `os.environ` 取凭证，必须走 `agent.secret_scope.get_secret`。
- 插件不得在 `initialize()` 缓存 `hermes_home`，必须按调用方传入的 home 做键。
- 后台线程必须经 `agent.memory_provider.spawn_context_thread`，不得裸起 `threading.Thread`。
- 参照实现：[disk-cleanup](../../plugins/disk-cleanup/__init__.py)。

### 3.4 C3 MCP 层

允许变更：新增 / 移除 MCP Server、调整工具白名单、设置超时与并发。

约束：

- 每个 MCP Server 需登记：数据来源、是否出网、读取 / 写入权限、失败降级方式。
- 私有数据库只给只读账号；写操作必须独立 server 并加审批。
- MCP 工具不得绕过工具集门控与审批门。

### 3.5 C4 Provider 层

| 类型 | 路径 | 说明 |
| --- | --- | --- |
| 模型供应商 | `~/.hermes/plugins/model-providers/<name>/` | 注册 `ProviderProfile`；本地 Ollama / vLLM 走 OpenAI 兼容端点 |
| 记忆后端 | `~/.hermes/plugins/memory/<name>/` | 实现 `MemoryProvider` ABC |
| 上下文引擎 | `~/.hermes/plugins/context_engine/<name>/` | 实现 `ContextEngine` |
| 平台适配器 | `plugins/platforms/<name>/adapter.py` | 按 [ADDING_A_PLATFORM.md](../../gateway/platforms/ADDING_A_PLATFORM.md) |

约束：

- 模型供应商只应声明能力与端点，不得偷改全局默认模型。
- 记忆后端必须声明数据落点与出网行为；本地自用默认选本地实现。
- 平台适配器不得修改 `os.environ`；YAML 走 `PlatformConfig.extra` 桥接。

### 3.6 C5 工具与工具集

仅当 MCP 与插件都无法满足时进入本层。

允许变更：

- 新增工具文件（`tools/` 下自动发现）。
- 调整 `toolsets.py` 中的工具分组。
- 为工具增加 `check_fn` 门控（服务不可达时不出现）。

约束：

- **默认不加入 `_HERMES_CORE_TOOLS`**；每个核心工具都会在每次 API 调用中发送。
- 新能力优先做成命名工具集，由会话来源按需折叠进来。
- 工具参数与返回必须结构化；不要把大段文本塞进描述。
- 涉及文件 / 网络 / 进程的工具必须有审批或沙箱路径。
- 变更必须附 1–2 个行为契约测试，不得写“变更检测器”测试。

### 3.7 C6 核心层

默认禁止。仅在以下情况考虑：

- 上游明确缺失且插件面无法扩展，且该能力对个人使用是刚需。
- 能用一个局部补丁解决，不引入新门面、新全局状态、新兼容别名。

若必须修改：

1. 先读对应区域的 `AGENTS.md`（`agent/`、`hermes_cli/`、`gateway/`、`tools/`）。
2. 记录上游 diff，形成可重放的补丁文件。
3. 补不变量测试：角色交替、系统提示字节稳定、profile 作用域。
4. 升级前先跑回归，再重放补丁。

### 3.8 前端层

| 前端 | 技术栈 | 允许变更 | 验证命令 |
| --- | --- | --- | --- |
| Desktop | Electron + Vite + React | 视图、皮肤、面板、RPC 调用 | `cd apps/desktop && npm run typecheck && npm run lint && npm test` |
| TUI | Ink (React) | 渲染、快捷键、斜杠面板 | 参见 [tui_gateway/AGENTS.md](../../tui_gateway/AGENTS.md) |
| Dashboard | FastAPI 路由 + SPA | 路由、面板、鉴权 | 参见 [web/AGENTS.md](../../web/AGENTS.md) |

约束：前端不得重建 core 的会话、工具、记忆逻辑；只做呈现与 RPC。

## 四、不可变更项（红线）

| 编号 | 禁止项 | 原因 |
| --- | --- | --- |
| R1 | 会话中途修改系统提示、工具集或重载记忆 | 击穿提示缓存，成本最高 |
| R2 | 破坏严格角色交替，或在循环中注入合成用户消息 | 多数供应商会直接报错或行为异常 |
| R3 | 插件修改核心文件 | 违反插件契约，升级即坏 |
| R4 | 移除或绕过 fail-closed 密钥守卫 | 多 profile 场景下会串号泄露 |
| R5 | 在仓内代码或测试中使用 compat 兼容路径 | CI 会拦截，且在移除日集中失效 |
| R6 | 关闭审批门、把高风险工具塞进 webhook 安全集 | 不可信输入可直接触发执行 |
| R7 | 安装未锁 SHA 的插件或依赖 | 供应链攻击面 |
| R8 | 在日志、文档、技能中写入明文密钥 | 泄露且难以回收 |
| R9 | 测试写入真实 `~/.hermes`，或让测试读源码文本 | 污染本机状态、产生假覆盖 |

## 五、安全规范

### 5.1 密钥与凭证

- 凭证只存 `~/.hermes/.env`；配置放 `config.yaml`。
- 代码读取统一走 `agent/secret_scope.py::get_secret`；multiplex 模式下未绑定作用域应 fail-closed。
- 插件与 `check_fn` 不得直接读 `os.environ`。
- 定期执行 `hermes doctor`，检查凭证有效性与环境异常。
- 轮换凭证后重启常驻进程，确认旧凭证已失效。

### 5.2 数据主权与出网（本地自用重点）

| 数据面 | 默认风险 | 本地化建议 |
| --- | --- | --- |
| 会话内容 | 记忆后端可能外发 | 选本地记忆实现，或关闭外部 provider |
| 辅助模型 | 压缩 / 标题 / 检索会发出摘要 | `auxiliary:` 指向本地模型 |
| 网络检索 | `web_search` / `web_extract` 必然出网 | 按需启用，敏感任务临时禁用 |
| 日志 | 可能包含路径、命令、片段 | 设置保留期，启用脱敏规则 |
| 会话库 | SQLite 明文 | 磁盘加密 + 定期离线备份 |

- 出网组件逐项登记到“出网清单”，默认拒绝新增。
- 网关默认绑定 `127.0.0.1`；需要外部访问时走反向代理 + 鉴权。
- 详细 egress 机制见 [egress-internals.md](../../website/docs/developer-guide/egress-internals.md)。

### 5.3 执行权限与沙箱

- 高风险动作启用审批：参照 [base_exec_approval.py](../../gateway/platforms/base_exec_approval.py)。
- 渠道访问策略按人 / 群 / 会话收紧：参照 [access_policy_mixin.py](../../gateway/platforms/access_policy_mixin.py)。
- Webhook 等不可信入口只允许安全工具集（`_HERMES_WEBHOOK_SAFE_TOOLS`，见 [toolsets.py](../../toolsets.py)）。
- 长任务、不可信代码优先跑在 `docker` / `ssh` / `modal` / `daytona` / `singularity` 后端，不用 `local`。
- 工具集最小化：默认关闭不需要的工具，尤其是 `terminal`、`browser_*`、`computer_use`。

### 5.4 供应链与依赖

- 依赖必须精确锁定；修改 `pyproject.toml` 后执行 `uv lock`。
- 插件只从 `plugin-catalog/` 安装，条目必须锁 40 位 SHA；被 `removed.yaml` 拉黑的一律拒绝。
- 安装前跑 `hermes plugins validate <path>`。
- 升级后跑 `hermes plugins doctor`，确认插件与真实运行时契约一致（旧的 `hermes plugins compat` 已在 2026-09 兼容窗口结束后移除）。
- 不执行来源不明的 `curl | bash` 安装脚本。

### 5.5 多 Profile 隔离

- 路径统一用 `get_hermes_home()`，禁止硬编码 `~/.hermes`。
- 一个进程可能服务多个 profile；任何缓存都要用 `hermes_home_key()` 做键。
- 子进程环境用 `served_profile_child_env`，不得 `os.environ.copy()`。
- 验证方式：两个 home 做 A→B→A 往返，确认无串号。

### 5.6 内容安全（提示注入）

- Webhook、网页、邮件、群消息一律视为不可信输入。
- 不可信内容不得直接进入系统提示；只能作为用户消息或工具结果。
- 对不可信输入禁用文件写入、终端执行、凭证读取类工具。
- 输出侧启用脱敏规则，避免把密钥、内网地址回显到聊天渠道。

### 5.7 审计与可观测

- 日志：`agent.log`（INFO+）、`errors.log`（WARNING+）、`gateway.log`；用 `hermes logs --level` 查看。
- 定时任务：关注失败、连续失败与超时，开启失败告警。
- 变更审计：记录变更人、层级、文件、回滚点、验证结果。
- 每次升级后跑一次 `hermes doctor` 与关键回归。

## 六、推进流程（六步）

| 步骤 | 动作 | 产物 | 验收 |
| --- | --- | --- | --- |
| P1 立项 | 写变更申请单，明确目标与非目标 | 变更申请单 | 目标可度量、边界清晰 |
| P2 选层 | 按 C0→C1→C2→C3→C4→C5→C6 选最低可行层 | 层级决策记录 | 能用技能解决就不写插件 |
| P3 实现 | 在隔离环境开发，使用临时 `HERMES_HOME` | 代码 / 配置 / 技能 | 不污染日常 profile |
| P4 验证 | 跑测试、doctor、兼容检查、相关 E2E | 验证记录 | 全部通过，无新增告警 |
| P5 上线 | 备份、灰度、保留回滚点 | 上线记录 | 可一键回退 |
| P6 归档 | 记录变更、经验、复现命令 | 执行日志 | 下次会话可直接接力 |

## 八、常见反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 直接 fork 核心实现业务 | 升级即冲突，成本持续累积 | 用插件或 MCP |
| 在插件里改全局 `os.environ` | 多 profile 串号 | 走配置桥接与作用域 API |
| 把新工具塞进 `_HERMES_CORE_TOOLS` | 每次 API 调用都付费 | 建命名工具集，按会话折叠 |
| 用记忆后端存全量聊天 | 成本高、隐私风险大 | 只存结论与偏好 |
| 会话中途热加载技能 / 记忆 | 缓存击穿 | 下次会话生效，或走用户消息注入 |
| 用 `skipif` 代替 OS 标记 | 测试在任何平台都不跑 | 用 `linux_only` / `macos_only` / `windows_only` |
| 测试里读源码做断言 | 假覆盖，阻止重构 | 提取纯函数后测试行为 |
| 日志里打印完整请求体 | 泄露凭证与隐私 | 脱敏 + 截断 |

## 九、阶段里程碑

| 阶段 | 目标 | 验收门槛 |
| --- | --- | --- |
| 阶段一 稳态 | 本地可用、可恢复 | 连续 7 天无人值守；重启可恢复上下文；日志无 WARNING 堆积 |
| 阶段二 扩展 | 个人能力面成型 | 10–15 个高频技能；私有工具全部 MCP / 插件化；升级后全部可用 |
| 阶段三 体系化 | 可审计的个人平台 | 有回归集；关键自动化有告警与人工兜底；升级回归可在 30 分钟内完成 |
