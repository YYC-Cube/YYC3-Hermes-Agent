# 08 · 上游 0.23.1 整树切换干跑报告

> 07 报告 §7.2/§7.3 约定的「0.23.0 发布后正式干跑」。执行日 2026-11-11（v0.23.0 发布后第 6 天）。
> 方法：fork 为 squash 导入（`ceb2a4a11f` 无上游祖先），rebase 模拟不可行 → 采用**锚点树三方对比 + blob 级 `git merge-file` 逐文件实测**（base = `v0.21.4+canary.20260925T065930Z`，ours = `main`，theirs = `upstream-v0.23.1` 浅取树完整）。脚本：`scripts/dryrun-0231.sh`；原始清单：`logs/dryrun-0231/`。

## 0. 结论速览

**推荐：维持方案 (a)（0.21.3 基线 + 定点 backport），正式否决当前窗口的整树切换，并将 07 §7.2-1 触发条件改写为「0.24.0（承诺完整 curated notes）发布后的下一个评估点」。**

理由三行：

1. **上游节奏已使「≥7 天无 hotfix 串」结构性不可满足**——v0.23.0（11-05）后 5 天即滚装 v0.23.1（11-10，+2,578 commits / 2,781 文件 / +151,690 −62,595）。等稳定窗 = 永远等不到；条件必须重定义而非硬等。
2. **实测冲突面 ≈ 07 预测，但重放成本随漂移单调上涨**——交集 84（07: 81），真冲突 61；剔除政策类（workflows/lockfile/资产/README）后**真人工决策 ≈ 13-23 文件**（07 预测 ≈20，偏差可解释）。核心源码 3 周 +5.9%（743,896 → 932,418 行）。
3. **切换收益未增加而风险已具象化**——0.23.1 无我们急需的引擎能力；其安全节 4 项可走 backport 渠道；实测还暴露了我方维护面缺口（.gitattributes ours 政策缺失，见 §4）。

## 4. 干跑暴露的新事实

1. **`.gitattributes ours` 政策缺失**（G8）：07 §7.3-1 要求「即刻提交 main」，实际从未落地；09 记载「已预置」失实。本报告修正该记载，并将政策改为**切换前临时应用、切换后移除**（理由：merge=ours 常驻会毒化日常 PR 对 `uv.lock`/`package-lock.json` 的正常合并——PR 侧合法依赖更新会被静默丢弃）。
2. **mcp_serve/compat 迁移负担已消失**：07 §4-3/4-4 预估的 cli.py + evals ×2 引用改造，实测我方树已不存在该引用面（上游生态演进使我方中间版本自然消化了它）。
3. **上游安全节 = 现成 backport 候选**（方案 (a) 渠道）：secret 掩码扩展（#149435/#148862/#149470）、审批门强化 curl|sudo bash 等（#87362/#148865/#141377/#87554）、网络边界（#145578/#145310）、shell-hook consent（#140984/#141034）。
4. **0.23.1 的实质修复**（plugin-catalog 2MiB→16MiB cap，#151860）不影响我方（无插件目录消费）。

## 5. 行动清单

1. **即刻（本 PR）**：08 报告 + 09 v1.2.0（修正「已预置」记载）+ 02 日志。
2. **本周期**：按方案 (a) 渠道评估 §4-3 的 4 个 backport 候选（逐项走分支+PR）。
3. **切换前临时政策**（若未来执行切换）：切换分支上先提交 `.gitattributes` merge=ours（pubilc/**、docs/hermes-agent-实施专家-*/**、.github/workflows/*、**/package-lock.json、**/uv.lock）+ `git config merge.ours.driver true`，切换合并完成后**立即移除**——不常驻 main。
4. **下一评估点 = v0.24.0**：其 notes 承诺完整 curated 内容（0.23 窗口的全部细节），且 0.23 节奏下 0.24 即下一个稳定锚；届时用 `scripts/dryrun-0231.sh`（改两个变量即可复用）重测。
5. **维持不做**：0.23.x 中途整树切换、批量 cherry-pick 非安全类、org 镜像同步。
