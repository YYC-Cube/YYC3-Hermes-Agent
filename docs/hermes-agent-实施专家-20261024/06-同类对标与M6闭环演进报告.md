## 三、演进建议（优先级排序）

1. **[M7] 上游 0.22 评估（下一个闭环对象）**：上游五日 +1,825 星证明 0.22.x 线是生态主航道；本分支停留 0.21.3 的窗口成本逐日上升。先出 06 报告（模块映射 + 合并决策），目标下轮完成。
2. **[M8] 把 M6 的修复变成防回归机制**：本次 37→0 的价值会随时间衰减，除非——preflight 脚本（版本门禁 + OSV + 安全定向测试一条命令）与上游周报自动化（可用 hermes cron 自调度）落地。
3. **跟随组织迁移**：OpenHands/goose/LibreChat 均已换仓库归属；本分支的 upstream remote 指向正确，但需在 M8 周报中加入「上游仓库迁移检测」。
4. **负载级 flake 治理**（进行中）：`test_approved_command_clean_slate` 与 runner 300s 文件上限两处基础设施 flake 已在收官 triage，完成后 M6 达成完全体。
5. **不追 UI 军备**：Open WebUI 当日发版式节奏属于产品型团队；本分支定位「个人可自我进化助理」，把自动化做厚比追发布频率更符合定位。
