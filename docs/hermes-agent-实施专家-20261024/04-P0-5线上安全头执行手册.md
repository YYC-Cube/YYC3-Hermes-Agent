# P0-5 线上安全头执行手册

## 一、当前事实

| 项 | 实测 |
| --- | --- |
| 域名 | `h-agent.yyc3.vip` |
| DNS | CNAME → `yyc-cube.github.io` |
| 源站 | GitHub Pages（`server: GitHub.com`） |
| CDN / 代理 | **无**（无 `cf-ray`，`server` 不是 `cloudflare`） |
| 已存在的安全头 | **0 / 5**（仅 `server`、`cache-control`） |
| Cloudflare 凭据 | 本机未发现 `cloudflared`，环境变量无 `CLOUDFLARE_*` / `CF_*` |
| 仓库侧已完成 | HUB 根页已加 CSP + Referrer meta |

结论：**仓库无法直接修改 DNS/CDN**。要完成 P0-5，需要在 Cloudflare 侧开启代理并注入响应头。

## 二、推荐路径：Cloudflare 代理 + Transform Rules

### 2.1 前置条件

- `yyc3.vip` 的 DNS 托管在 Cloudflare（或可迁移 NS）。
- 能访问 Cloudflare Dashboard 的 Zone 管理员，或持有最小权限 API Token：
  - `Zone:Read`
  - `Zone Settings:Edit`
  - `Zone Rulesets:Edit`
  - `DNS:Edit`（仅首次接入/切换 NS 需要）

### 2.2 接入与代理

1. Cloudflare Dashboard → Add site → `yyc3.vip`。
2. 按提示把 NS 切到 Cloudflare 分配的 nameserver。
3. DNS 记录保持：`h-agent` CNAME → `yyc-cube.github.io`，**Proxy status = Proxied（橙色云）**。
4. SSL/TLS → Overview → **Full (strict)**。
5. 确认 GitHub Pages 自定义域仍为 `h-agent.yyc3.vip`（`pubilc/CNAME` 已固定）。
6. 验证：

```bash
dig +short h-agent.yyc3.vip CNAME
curl -sS -I https://h-agent.yyc3.vip/ | grep -i '^server:'
# 期望 CNAME 仍指向 GitHub Pages；server 变为 cloudflare
```

### 2.3 Transform Rule：注入响应头

Rules → Transform Rules → **Modify Response Header** → Create rule：

- **Rule name**：`YYC3 security headers`
- **When incoming requests match**：`Custom filter expression`
  - Field: `Hostname` / Operator: `equals` / Value: `h-agent.yyc3.vip`
- **Then**：Set static headers：

| Header | Value |
| --- | --- |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` |

> 首次不要直接上 `preload` 和强 CSP。先观察 1–2 周，再把 HSTS 加到 `preload`；CSP 先用 `Content-Security-Policy-Report-Only`，确认 Docusaurus 的 inline runtime、Algolia、图片 CDN 不被误伤后再转正式头。

### 2.4 CSP 建议（第二阶段）

`h-agent.yyc3.vip/` 是单文件 HUB，已有严格 meta CSP；`/docs/` 是 Docusaurus，需要更宽松的策略。建议先在边缘加 Report-Only：

```text
Content-Security-Policy-Report-Only: default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' data:; connect-src 'self' https://*.algolia.net https://*.algolianet.com; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
```

观察无阻断后再改为 `Content-Security-Policy`。HUB 的 meta CSP 与边缘头会叠加（取更严格者），这是预期行为。

## 三、验收

```bash
for u in https://h-agent.yyc3.vip/ https://h-agent.yyc3.vip/docs/; do
  echo "== $u =="
  curl -sS -I --max-time 20 "$u" | grep -Ei \
    '^(HTTP|strict-transport-security|content-security-policy|x-frame-options|x-content-type-options|referrer-policy|permissions-policy|server)'
done
```

验收标准：

- [ ] `Strict-Transport-Security`
- [ ] `X-Content-Type-Options: nosniff`
- [ ] `X-Frame-Options: DENY`
- [ ] `Referrer-Policy`
- [ ] `Permissions-Policy`
- [ ] `server: cloudflare`（代理生效）
- [ ] 首页、`/docs/`、`/api/skills.json` 均 200
- [ ] 站点搜索、Algolia、图片加载无 CSP 报错

## 四、回滚

1. Transform Rule 禁用或删除。
2. 如需完全回退：DNS 记录改回 **DNS only（灰色云）**，等待 TTL 生效。
3. HSTS 不要在有风险时启用 `preload`；一旦 preload，回滚需要数周。

## 五、API 方式（可选）

如果使用 API Token，可先读取 Zone：

```bash
export CF_API_TOKEN="***"
export CF_ZONE_ID="***"
curl -sS -H "Authorization: Bearer $CF_API_TOKEN" \
  "https://api.cloudflare.com/client/v4/zones/$CF_ZONE_ID" | jq '.result.name,.result.status'
```

Transform Rules 的 ruleset 创建/更新建议在 Dashboard 完成一次，再用 API 导出备份，避免手写 JSON 出错。**本仓库不保存任何 Cloudflare 凭据。**

## 七、复查结论（2026-10-24 第二次会话）

1. **线上复核**：`h-agent.yyc3.vip` 仍 GitHub Pages 直连（`server: GitHub.com`、Fastly 头、无 `cf-ray`），安全头 0/5。
2. **NS 归属**：`dig NS yyc3.vip` → `dns29.hichina.com` / `dns30.hichina.com`。域名注册/DNS 在阿里云，**Cloudflare 侧尚无该 zone** —— 即使持有 API Token，也必须先由用户在阿里云控制台把 NS 改为 Cloudflare 分配值并等待 `active`。
3. **本机凭据**：无 `CF_*` / `CLOUDFLARE_*` 环境变量、无 cloudflared/wrangler/flarectl、无 shell profile 引用；第二会话无法代执行 Cloudflare 写操作。
4. **交付物**：`scripts/p05-cloudflare-configure.sh` —— 把第二节全部 Dashboard 步骤固化为幂等 API 调用：

```bash
export CF_API_TOKEN='***'   # Zone:Read / DNS:Edit / Zone Settings:Edit / Zone Rulesets:Edit

# 首次（zone 未接入时）：创建 zone 并打印应设置的 NS，然后去阿里云控制台改 NS
bash scripts/p05-cloudflare-configure.sh --apply --add-zone --account-id <32位AccountID>

# NS 生效后：先 dry-run 核对，再应用
bash scripts/p05-cloudflare-configure.sh
bash scripts/p05-cloudflare-configure.sh --apply

# 第二阶段（观察 1–2 周后）：附加 CSP Report-Only
bash scripts/p05-cloudflare-configure.sh --apply --with-csp-report-only
```

5. **验收**：脚本身末自动 `curl -I` 打印当前响应头；完整验收用第三节命令，标准不变。

## 八、方案 B 执行手册（已选定）：阿里云 DCDN 子域级 CNAME 接入

**决策（2026-10-24）**：`yyc3.vip` 下挂 70+ 项目三级域名，为避免整区 NS 迁移的波及，选定**方案 B**——仅把 `h-agent` 子域通过 CNAME 接入 CDN。选型**阿里云 DCDN（全站加速）海外区域**：与域名同账号（云解析 hichina）、原生支持 CNAME 接入、仅海外节点无需 ICP。本机 aliyun CLI 未配置（无 `config.json`），以下操作需用户在控制台执行，AI 逐步代验收。

### 8.1 步骤

1. 开通 **DCDN**（按量后付费；仅添加域名不计费，流量按量计费——纯静态文档站成本可忽略）。
2. DCDN 控制台 → 域名管理 → **添加域名**：加速域名 `h-agent.yyc3.vip`；源站类型「域名」→ `yyc-cube.github.io`，端口 443；加速区域选**仅中国内地以外**。
3. 所有权验证：按提示在云解析（hichina）加一条 **TXT 记录**——记录级操作，不动 NS、不影响其他 70+ 子域。
4. 添加成功后复制 DCDN 分配的 **CNAME 目标值**（形如 `xxx.w.kunlungr.com`）。
5. HTTPS：该域名 → HTTPS 配置 → 开启并**申请免费证书**（个人测试证书，DNS 验证自动完成）；开启「强制 HTTPS 跳转」。
6. 回源确认：回源 Host 默认 = 加速域名（`h-agent.yyc3.vip`），**保持不变**——GitHub Pages 依赖该 Host 返回正确内容。
7. **自定义响应头**：该域名 → 缓存配置 → 自定义 HTTP 响应头，添加第二节 2.3 表的 5 类头（HSTS 先不含 preload；CSP 后置按 2.4 节节奏）。
8. **切换流量（回滚点）**：云解析 DNS → `yyc3.vip` → 把 `h-agent` 的 CNAME 记录值从 `yyc-cube.github.io` 改为步骤 4 的 DCDN 值（TTL 10 分钟）。
9. **验收**：执行第三节 curl——期望 5 类头齐全、`server` 不再是 `GitHub.com`、首页/`/docs/`/`/api/skills.json` 均 200。

### 8.2 回滚与注意

- **回滚 = 把 `h-agent` 的 CNAME 改回 `yyc-cube.github.io`**，分钟级生效；随后可删除 DCDN 加速域名，停止一切计费。
- GitHub Pages 自定义域保持验证状态（`pubilc/CNAME` 已固定）；DCDN 回源 443，源站证书对 `h-agent.yyc3.vip` 有效（Pages 已签发）。
- 方案 A（Cloudflare 全区迁移 + 灰云默认 + `p05-cloudflare-configure.sh`）与方案 C（meta 兜底 2/5）保留为备选；若未来切 CF，本节配置作废。
